# Этап 4A — защищённое чтение опубликованных материалов из PostgreSQL

Источник переноса: Webflow **dgimos.design.webflow.com** (site `6aca6bde03aad0f2e3c19259`).
На 13.10.2026 через Webflow API сверены 33 опубликованные статические страницы с 33
снимками Next.js: совпадают URL-slug и имеющиеся SEO title/description. Webflow API
показал четыре коллекции CMS. Отдельные файлы в Webflow Assets API отсутствуют;
фоновые изображения/внешние URL потребуют визуальной проверки и отдельной инвентаризации.

## Что добавлено

- `0003_editorial_publication.sql`: поле `reviewed_by`, CHECK для статуса
  `published` и триггер аннулирования подтверждения при изменении текста, заголовков
  или источника. Публикация должна выполняться отдельным действием после редакторской
  проверки. Это **не** система аутентификации редакторов.
- `apps/web/src/data/published.ts`: серверный read-only PostgreSQL adapter со строгой
  фильтрацией `published + checked_at + reviewed_by + published_at`, валидацией
  блоков и параметризованным запросом.
- `/[slug]` подхватывает разрешённую запись из БД как приоритетную, если задан
  `CMS_PUBLIC_READS=true`; исходные Webflow snapshots остаются fallback для
  известных маршрутов. Для новых URL без подтверждённой записи будет 404.
- CI применяет миграцию к временной PostgreSQL и проверяет запрет публикации без
  подтверждения, разрешение после подтверждения и автоматический отзыв после правки.

## Важно

По умолчанию `CMS_PUBLIC_READS=false`, `SITE_CUTOVER=false`.
Никакая запись `webflow_cms_staging` не публикуется через этот механизм.
При включённом чтении отсутствие соединения с PostgreSQL — серверная ошибка,
не автоматический показ черновиков. HTML/JS не передаются в контентные блоки.
Старые статические снимки Webflow **не означают** юридической проверки;
перед запуском продакшена потребуется отдельная редакционная приёмка.

Это промежуточный read-only слой, **не завершённая интеграция Payload CMS**.
Следующий этап: аутентификация и роли Payload, перенос медиа, аудит публикаций
и корректный sitemap для новых подтверждённых URL. Не включайте SITE_CUTOVER
до E2E-проверки и подтверждения маршрутов.

Пример последовательности **только на тестовой БД**:

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/migrations/0001_initial.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/migrations/0002_webflow_cms_staging.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/migrations/0003_editorial_publication.sql
pnpm migration:apply
pnpm migration:cms:apply
# Чтение подтверждённых записей активируется только после ручной проверки:
# CMS_PUBLIC_READS=true (добавить в окружение Next.js)
```
