# Еженедельная юридическая ревизия сайта dgi-pravo.ru

Еженедельная проверка работает **отдельно** от выпуска новостей, наполнения судебной практики и проверки интерфейса.

## Расписание и где искать результаты

- Каждый понедельник в 08:25 по Москве GitHub Actions запускает `Weekly full-site legal source inventory (read-only)` с **основной ветки `main`**.
- Задание `Еженедельная юридическая ревизия ДГИ` по понедельникам выполняет содержательную проверку законодательства и корректирует только подтверждённые сведения, если доступен защищённый путь публикации. Обычный запуск — утром, отдельно от автоматического сбора данных.
- Ветка материала сайта: `infra/coolify-russian-vps`.
- Параметры и запреты: [`config/weekly-legal-audit.json`](../config/weekly-legal-audit.json).
- Сборщик: [`scripts/weekly_legal_audit.py`](../scripts/weekly_legal_audit.py).
- Файл `weekly-legal-audit-report.json` сохраняется как GitHub Actions artifact **`legal-weekly-evidence`** на 30 суток.
- Выпуск сайта через репозиторий `ymaslen77-tech/vps-infrastructure`, приложение Coolify `dgi-web`. Не изменять базу данных без безопасного редакционного механизма.

## Обязательный полный охват

1. Использовать список всех опубликованных URL и действующих редакционных страниц CMS. Статические `pages-*.json` — только дополнительный источник, потому что в рабочей версии материалы могут читаться из базы `editorial_pages`.
2. Проверить нормы федерального, московского и областного законодательства, порядок действий, документы, сроки, размеры платежей, компетенцию органов, исключения и юридические последствия.
3. Дополнительно проверить правовые утверждения в новостях и **редакционные выводы** по судебным делам. Судебные тексты и исходные PDF — неизменяемые исторические документы.
4. Найти новые профильные изменения нормативной базы и официальных процедур, не дублируя ежедневный новостной конвейер.
5. На каждое подтверждённое изменение сохранить след: URL нашей страницы, старая и новая формулировки, номер и статью нормативного акта, ссылки на официальный источник, редакцию, дату вступления в силу, переходные правила и дату проверки.
6. Только после проверки собрать приложение, пройти тесты, выпустить обновление и подтвердить новую формулировку по публичному HTTPS-URL.

## Иерархия источников

Первичные источники — `pravo.gov.ru`, `publication.pravo.gov.ru`, `mos.ru`, `mosreg.ru`, Росреестр, ФНС, уполномоченные ведомства и официальные судебные сайты. `consultant.ru` и `garant.ru` — для дополнительного поиска и сверки, не как замена официальному тексту.

Не путать действующий закон, опубликованную будущую поправку, законопроект и неподтверждённое сообщение СМИ.

## Что разрешено автоматически

- Получать и индексировать общедоступные тексты, даты и ссылки; искать предполагаемые изменения.
- Вносить **доказанные** исправления в фактический источник опубликованной страницы и добавлять документы, непосредственно относящиеся к жилищным и имущественным вопросам Москвы и области.
- Публиковать проверенные изменения, только если сработали все защитные проверки и **доступен способ обновить CMS либо действующую ветку, с которой действительно обслуживается маршрут**.
- Составлять недельный отчёт с количеством реально проверенных страниц и ссылками на исправления.

## Чего система не делает

- Не меняет закон из-за HTTP 403, ошибки DNS, временной недоступности портала или устаревшей поисковой выдачи.
- Не объявляет непроверенный материал проверенным и не придумывает юридические основания, нормы, сроки и судебные результаты.
- Не пытается переписать официальные определения суда и защищённые PDF.
- Не меняет исторические JSON как замену редакции CMS: если маршрут обслуживается базой, обновление требует проверки и редактирования именно базы.
- Не публикует правовые изменения, если не удалось подтвердить правовую норму или результат доставки на VPS.

## Запуск вручную

GitHub Actions → `Weekly full-site legal source inventory (read-only)` → `Run workflow`. Либо локально из корня репозитория:

```bash
python3 scripts/weekly_legal_audit.py --config config/weekly-legal-audit.json --output weekly-legal-audit-report.json
```

Полученный отчёт — **вспомогательный перечень проверяемых фактов**, а не юридическое заключение и не основание для автоматического редактирования. За содержательную правовую проверку отвечает отдельно настроенная еженедельная задача.
