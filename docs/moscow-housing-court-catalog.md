## Официальные источники и реализация
1. **Суды Москвы, первая инстанция, гражданские дела**: [набор открытых данных](https://data.mos-gorsud.ru/opendata/1577116594824-casesgroupfirstcivilhxvgb), размер выгрузки порядка 620+ MB. В GitHub Variables задан `COURT_DATASET_URL`. Автоматический парсер `court_catalog.py` принимает её JSON **после проверки реальной структуры**.
2. **Суды Москвы, первая инстанция, административные дела**: [каталог](https://data.mos-gorsud.ru/opendata). Включить после проверки непосредственного URL отдельного набора.
3. **Мосгорсуд, гражданская апелляция**: [официальный набор](https://data.mos-gorsud.ru/opendata/1577117744056-casesgroupmgsappealcivilwtxga); точный URL JSON-выгрузки и структуру надо дополнительно проверить.
4. **Мосгорсуд, административная апелляция**: [реестр открытых данных](https://data.mos-gorsud.ru/opendata?topicId=dd0a3ade-f987-4f82-ace3-456bbc716171); нужен конкретный скачиваемый набор.
5. **Второй кассационный суд**: [официальное судебное делопроизводство](https://2kas.sudrf.ru/). Пока только тщательно отобранные вручную официальные карточки, никакого массового HTML-парсинга или обхода ограничений.
6. **Арбитражные суды**: [КАД](https://kad.arbitr.ru/). Массовый сбор не включён: сначала проверить права и разрешённый машинный доступ.
7. **Верховный Суд**: [официальный сайт](https://vsrf.ru/) и [официальные обзоры](https://vsrf.ru/documents). Тематические обзоры и индивидуальные определения хранить отдельно: обзор не равен карточке конкретного дела.

**Никаких непроверенных дат, исходов, «правовых позиций» и автоматической публикации.** У публичной карточки должны появляться сведения о результате только после чтения судебного акта. Результаты дел предыдущих инстанций не выводить автоматически из карточки кассации.

## Как устроена база
- `data/court-catalog.jsonl`: долговременный начальный JSONL-индекс кандидатов, включает `court`, `number`, `uid`, `official_case_url`, `topics`, `dgi_party`, `verification`. **ФИО, адреса, названия сторон, тексты судебных актов и результат дела не сохраняются.**
- `court_catalog.py`: потоковое чтение больших JSON через `ijson`; строгая проверка URL и тем; дедупликация экземпляров по суду, номеру и URL; группировка разных инстанций условным ключом УИД; накопление следующих кандидатов без удаления предыдущих записей.
- `tests/test_court_catalog.py`: тесты фильтрации жилищной тематики, ДГИ, ссылок, приватности, дедупликации и поддерживаемой структуры.
- `.github/workflows/moscow-housing-court-catalog.yml`: **еженедельно по понедельникам в 07:30 МСК**, проверка тестов, скачивание официального JSON, запись до 2500 новых кандидатов в отсортированный индекс GitHub. Реальная работоспособность скачивания/схемы требует первого прогона.
- `.github/workflows/weekly-dgi.yml`: старую еженедельную загрузку в переполненную CMS отключили. Она доступна **только вручную**, по умолчанию без загрузки.

## Первый запуск и контроль
1. Перейти на GitHub → Actions → **Moscow housing court catalog — official open data** → **Run workflow**.
2. Первый запуск: `write_catalog=false`, `max_new=100`. Проверьте, что скачивание 600+ MB завершилось, тесты прошли, а отчёт показывает положительное число relevant. При нуле или ошибке схемы не считать выгрузку валидной, поправить адаптер.
3. Только после успешного dry-run запустить `write_catalog=true`, с лимитом 2500 кандидатов. Коммит появится в `data/court-catalog.jsonl`. Изменения следует проверять по примерам из нескольких категорий.
4. Перед построением **действительно исчерпывающей** базы перейти от GitHub JSONL к поисковому хранилищу (например PostgreSQL + полнотекстовый индекс): нужны высокая ёмкость, поиск по нескольким инстанциям, автоматическая проверка дублей и аудит первоисточников. Публичный Webflow должен отображать отобранные и проверенные материалы, а не все необработанные карточки.

## Контроль качества
- Не смешивать `case_metadata_only` (карточка дела) с `verified_primary` (прочитан сам судебный акт).
- Не объединять два дела лишь по одной фамилии, номеру без суда или совпадению категории.
- Отдельно отмечать, когда апелляция/кассация **не проверена**.
- При повторном экспорте считать уникальные карточки, не суммировать количества выгрузок.
- Никогда не заявлять о «100% полноте»: отдельные решения не публикуются судами или скрыты по закону; судебные базы регулярно обновляются.
