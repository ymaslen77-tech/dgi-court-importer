## Критические блокеры органического продвижения

1. **Нет индексируемых URL:** `robots.txt` — `Disallow: /`, `X-Robots-Tag` — `noindex, nofollow, noarchive`, `sitemap.xml` — пустой. Это ожидаемо до юридической приёмки, но означает нулевую готовность к органическому поиску сейчас. Важное уточнение Google: `Disallow` не гарантирует исключения URL из результатов, а блокировка краулинга может мешать роботу увидеть `noindex`. Поэтому после правовой приёмки потребуется отдельная согласованная схема открытия.
2. **Юридическая достоверность (тематика YMYL):** 20 нормативных документов без подтверждённых полных сводных редакций, семь регламентов ДГИ без заключительной проверки, 18 тематических инструкций не допущены к публикации и 37 исторических карточек без полного допуска решений. Не включать индексацию только ради SEO.
3. **Поисковая аналитика и реальные сигналы:** пока нет подтверждённого доступа к данным Google Search Console / Яндекс Вебмастера. Следует подтвердить сайт, добавить правильный sitemap после правового допуска, видеть Google Page Indexing / Яндекс Диагностику, запросы и CTR; выдумывать эти цифры нельзя.

## SEO-практики с официальным подтверждением, в порядке приоритета

1. **Правовое качество и прозрачность:** выводить реальные редакционные данные (имя автора/проверившего, подтверждённый профессиональный опыт, источник, дата проверки), только когда есть доказательства. В первую очередь оформлять актуальные оригинальные инструкции по конкретной задаче, а не автоматически размножать одинаковые статьи. Google: [helpful, reliable content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content); Яндекс: [качество сайта и экспертные сигналы](https://yandex.ru/support/webmaster/en/search-quality).
2. **Кластеры вопросов + внутренняя перелинковка:** «жилищный учёт» → признание малоимущим / перерегистрация / отказ / снятие / обжалование; «соцнаём» → вселение / обмен / изменение договора / выселение. Связи — реальные ссылки `<a href>` на действующие страницы, никакого множества doorway-страниц. [Рекомендации Яндекса по структуре](https://yandex.ru/support/webmaster/en/recommendations/site-structure).
3. **Управление URL:** только `https://dgi-pravo.ru`, постоянный 308 `www` → apex, индивидуальные `canonical` только для законно открытых страниц, `sitemap` только одобренных страниц. [Google canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [Яндекс canonical](https://yandex.ru/support/webmaster/ru/robot-workings/canonical).
4. **JSON-LD:** WebSite на главной, BreadcrumbList для фактической цепочки, WebPage/Article только в случаях, когда свойства и видимый текст совпадают. FAQ-разметку и авторов не фабриковать; Google может не показывать rich snippets даже при корректной схеме. [Google structured data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies), [Site Names](https://developers.google.com/search/docs/appearance/site-names).
5. **Яндекс IndexNow:** поддерживается Яндексом; подключать **только после разрешения индексировать конкретные страницы**, с ключом на собственном домене и проверкой URL по базе approved. Не посылать черновики. [Официальная документация](https://yandex.ru/support/webmaster/ru/indexing-options/index-now).
6. **AI Overviews / AI Mode / поисковые ассистенты:** специальные файлы `llms.txt`, «AI schemas» и тайные GEO-теги для Google не требуются. Google советует те же базовые требования SEO: индексируемость, оригинальные ответы, доступный текст, корректные источники и соответствие видимой страницы данным разметки. [Официальное руководство Google](https://developers.google.com/search/docs/appearance/ai-features); [обновление Google 2026](https://developers.google.com/search/blog/2026/05/a-new-resource-for-optimizing).
7. **Удобство и скорость:** реальные Core Web Vitals — LCP не более 2,5 сек, INP не более 200 мс, CLS не более 0,1 на 75-м перцентиле; фиксировать в Search Console и полевых метриках, а не выдавать синтетические результаты за реальный опыт. [Google CWV](https://developers.google.com/search/docs/appearance/core-web-vitals).
8. **Исследовательские гипотезы:** оригинальные сравнительные таблицы процедур, контрольные списки, алгоритмы выбора юридического маршрута, дерево решений по категориям заявителей и поисковик судебной практики по проверенным формулировкам. Проверять полезность, конверсию, органические запросы и устранение тупиков навигации, а не гарантировать эффект.
9. **Не применять:** накрутку поведенческих факторов, подставные отзывы, покупные SEO-сетки, выдуманные юридические квалификации, массовые автоматически сгенерированные неточные страницы или ложные даты обновления.

## Порядок финального SEO-релиза

1. Юридический допуск подтверждённых публичных страниц с действующими законами, ссылками, полными регламентами и ответственным проверяющим; материалы без допуска исключить из индекса.
2. Верификация домена в Google Search Console и Яндекс Вебмастере, проверка мобильного показа, Core Web Vitals, ошибок и реальных поисковых запросов.
3. Запустить на отдельном Neon staging интеграционный тест: `SITE_CUTOVER=true`, `SITE_RELEASE_APPROVED=yes`, `SITE_URL=https://dgi-pravo.ru`, только `editoriallyApproved=true` / утверждённые строки БД могут индексироваться.
4. После соответствующего правового решения настроить `robots.txt` для обхода одобренных страниц, снять `X-Robots-Tag noindex` **только с них**, сгенерировать sitemap для утверждённых URL. Структурированные данные должны соответствовать видимому тексту.
5. Пройти URL Inspection, Rich Results Test и мобильную/десктопную проверку на реальном production.
6. Установить ежемесячное обновление и правовую сверку изменившихся актов; информировать Яндекс IndexNow только при утверждённых изменениях, если подключён ключ.
7. Снять блокировки только после подтверждения всех пунктов. Никакой SEO-оптимизатор не гарантирует топ выдачи.
