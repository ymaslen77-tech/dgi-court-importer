# Перенос жилищного портала Webflow → Next.js: стадия 1

## Что уже реализовано

- Исходный сайт: https://dgimos.webflow.io; ID Webflow `6aca6bde03aad0f2e3c19259`.
- Новое приложение: `apps/web`, Next.js + TypeScript + Tailwind CSS, в **этом же** репозитории с Python-импортёрами.
- Снимок **33 публичных статических URL**, тексты основных элементов (H1–H4, абзацы, ссылки), прежние SEO title/description. Шесть файлов `apps/web/src/data/pages-0.json` … `pages-5.json`; исходная страница `source` сохранена для проверки.
- Архивная страница `internal-housing-design` не переносится в индексируемые публичные маршруты.
- Снимок **22 опубликованных метаданных судебных дел**, без утверждений о результатах и без персональных данных: `legacy-cases.json`. Их оригинальные судебные акты ранее не верифицированы.
- Из `data/court-catalog.jsonl` показываются официальные кандидаты судебных карточек (16 по начальной выборке). Условия выдачи объясняются посетителю; это не проверенный судебный результат.
- Работают отдельные URL-пути и серверная выдача HTML, заголовки, адаптивные страницы, простой фильтр судебных дел, `sitemap.xml`, `robots.txt`.
- Переключатель `SITE_CUTOVER=false` по умолчанию выключает индексацию **тестового развёртывания** и оставляет canonical на оригинальный Webflow. Не ставьте `SITE_CUTOVER=true` до QA, переноса домена и DNS.
- `db/migrations/0001_initial.sql` — стартовая схема PostgreSQL: страницы, судебные дела, инстанции, источники, импорт. **Пока не применяется автоматически**, Production DB не подключена.
- `scripts/export-webflow.mjs` — ручной API-экспорт страниц и всех CMS-коллекций в игнорируемую локальную `.migration/webflow`; не выполняется в CI, не пишет в публичную систему.

## Локальный запуск

```bash
corepack enable
pnpm install --no-frozen-lockfile
pnpm test
pnpm typecheck
pnpm dev
```

Откройте http://localhost:3000. Node.js 22 или новее. Пример настройки: `apps/web/.env.example`. PostgreSQL для этих страниц пока не требуется: они загружаются из фиксированных снимков, а не из базы данных.

## Архитектурный принцип

```text
apps/web (Next.js 16, content snapshots, SEO, court search v1)
db/migrations (PostgreSQL schema — planned persistent storage)
court_catalog.py + importer.py + news_importer.py (existing Python jobs)
.github/workflows (previous importer workflows + new website CI)
```

Судебные импорты и существующие расписания в `main` не затрагиваются. Внесённые данные из CMS не дополняются вымышленными юридическими фактами.

## Что ещё не сделано

1. **Pixel-accurate перенос визуальных секций Webflow:** есть текст и базовый строгий чёрно-красно-белый дизайн, но фоновые изображения, медиа, интерактивные секции и оригинальные скрипты требуют отдельного переноса/QA.
2. **Payload CMS и PostgreSQL runtime:** схема БД подготовлена, но Payload, админка, рабочие миграции, роли и полнотекстовый судебный поиск пока не интегрированы. Их нужно внедрить после проверки стартовой сборки.
3. **Обязательное SEO QA:** проверить 33 URL, структуру заголовков, каноникал, перенесённые внутренние ссылки, метаописания, robots и sitemap против действующего сайта. У нескольких старых страниц в Webflow могут быть потенциальные дубли/неудачные заголовки.
4. **Полный CMS-импорт:** экспорт новостей, нормативных документов, ситуаций, медиа и судебных карточек с валидацией и безопасной обработкой персональных данных. На стадии 1 есть только снимок опубликованной судебной метаинформации.
5. **Доступность и производительность:** Lighthouse, мобильная проверка, формы и функциональность фильтров, ссылки на официальные источники.
6. **Развёртывание:** нет PROD DNS, новых учётных записей и отключения Webflow; нельзя называть это завершённым переносом.

## Правила запуска

- Не менять DNS, домен и доступность Webflow до полного QA и приемки.
- Не публиковать автоматом судебные акты со статусом `case_metadata_only` либо `secondary-material-needs-primary-act-review`.
- Не копировать в GitHub приватные CMS-данные или секреты. Каталог `.migration/` в .gitignore.
- Сохранять все опубликованные slug; если URL приходится менять, явно задавать 301 и проверять цепочки переадресаций.
- Редакционная проверка дат/актуальности законодательства проводится отдельно от механического переноса текста.
- После подключения БД проверять миграции на тестовом PostgreSQL и делать резервное копирование до изменения схемы.

## Этап 2: PostgreSQL, тестовый импорт данных

Добавлены scripts/lib/prepare-migration-data.mjs и scripts/import-snapshots-to-db.mjs.
Импортируются 33 публичные страницы Webflow в статусе review, 22 старые
непроверенные карточки и кандидаты из data/court-catalog.jsonl.
Все судебные карточки остаются act_verified=false и без опубликованных исходов.
Заголовки ранее опубликованных карточек с неподтверждёнными выводами не копируются.
Повторный импорт через upsert не должен перезаписывать материалы со статусом
verified или published. Связь инстанций по УИД — будущая отдельная процедура.

Локально: установите Node.js 22, pnpm, Docker Compose и клиент psql.
Скопируйте .env.example в .env, замените пароль и загрузите переменные
POSTGRES_PASSWORD, POSTGRES_PORT, DATABASE_URL в окружение.
Выполните docker compose up -d database; pnpm install --no-frozen-lockfile;
pnpm migration:dry-run; psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/migrations/0001_initial.sql.
Только на тестовой БД выполните pnpm migration:apply.

CI db-checks запускает отдельный PostgreSQL 17, накатывает схему, импортирует
данные дважды и проверяет отсутствие дублей и ложной публикации.
Приложение Next.js пока отображает локальные снимки, а не БД; Payload CMS,
авторизация редакторов и поиск по PostgreSQL ещё не подключены.
Webflow/DNS остаются без изменений.

## Additional fail-closed cutover setting

Even if SITE_CUTOVER=true is set accidentally, the Next.js public app continues
as staging/noindex until SITE_RELEASE_APPROVED=yes **and** SITE_URL identifies a
valid HTTPS production origin outside Webflow and localhost. Do not set this
flag before legal, visual, security and SEO sign-off. This flag does not itself
verify content or configure DNS, CMS or backups.
