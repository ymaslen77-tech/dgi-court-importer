# Расширение судебной базы ДГИ: источники и правила

## Реестр официальных источников

| Источник | Назначение | Автоимпорт |
| --- | --- | --- |
| [Мосгорсуд, открытые данные](https://data.mos-gorsud.ru/opendata) | Структурированные гражданские дела первой инстанции; отдельные наборы апелляций/административных дел | Для первого гражданского набора: подготовлен, требует проверки реальной схемы в Actions |
| [Мосгорсуд](https://mos-gorsud.ru/) | Карточки дел и тексты судебных актов | Только ручная сверка; парсер актов не реализован |
| [Второй кассационный суд](https://2kas.sudrf.ru/) | Кассационные дела | Только редакционный просмотр; парсер не реализован |
| [Картотека арбитражных дел](https://kad.arbitr.ru/) | Арбитражные дела | Только редакционный просмотр; парсер не реализован |
| [Верховный Суд РФ](https://vsrf.ru/) | Определения и обзоры | Только редакционный просмотр; парсер не реализован |

Не подменяйте число *карточек дел* числом *судебных решений*. Наличие карточки не означает, что опубликована резолютивная часть, доступна мотивировка или решение вступило в силу.

## Модель одной судебной тяжбы

Одна юридическая тяжба может иметь несколько независимых записей об актах разных инстанций. Текущая коллекция Webflow `Судебная практика ДГИ` расширена следующими полями:

- `identifikator-sudebnogo-spora`: `uid:<УИД>`, когда у исходной записи реально есть УИД. При отсутствии УИД — уникальный `candidate:<hash>`; автоматического связывания в таком случае нет.
- `sudebnaya-instanciya`: явно подтверждённая инстанция. Для конкретного набора `casesgroupfirstcivil` выставляется «Первая инстанция»; для иных источников остаётся «Не определена».
- `istoriya-peresmotra`: редакционно проверенные сведения об иных инстанциях.
- `sudebnyy-akt-proveren`: `false` для каждой импортированной записи, пока редактор не сверил её первоисточник и резолютивную часть.
- `tema-zhiznennoy-situacii`: тематическая классификация после редакторской проверки.

Существующие `unikalnyy-identifikator`, `svyazannye-nomera-instanciy`, `status-peresmotra`, `rezultat-rassmotreniya`, `oficialnyy-istochnik`, `publikaciya-sudebnogo-akta`, `status-verifikacii` сохраняются.

**Ограничение:** общий УИД — техническая гипотеза связи, не юридическое доказательство тождества актов. Публичная группировка нескольких актов требует сверки инстанций, номеров и источников. Автоматическое объединение по только совпадению имени стороны или похожему номеру запрещено.

## Редакторский порядок

1. Импортировать не больше установленного лимита в **Webflow CMS Draft**. Не публиковать автоматически.
2. Для каждой записи зафиксировать URL оригинальной карточки дела или акта. Убедиться, что ДГИ действительно участник.
3. Найти **сам судебный акт**, идентифицировать суд, дату, номер, резолютивную часть. Не брать юридический результат из `publishingState` без текста решения.
4. Проверить апелляцию, кассацию, сведения о вступлении в силу, при наличии.
5. Обезличить персональные данные, где требуется; отказаться от выдачи предположений за факт.
6. Заполнить результат и `sudebnyy-akt-proveren=true` только после первичной проверки судебного акта.
7. Публиковать редакционно проверенный материал отдельно; добавить связи на нормы и жизненные ситуации.

## Новые CMS-коллекции сайта

- `Нормативные документы ДГИ` — ID `6acbb1ca75f0fd4e89dba736`. 4 исторически подтверждённых постановления в черновиках; их актуальность на октябрь 2026 **не сверена**.
- `Юридические ситуации с ДГИ` — ID `6acbb1cb3b6b24eada522db4`. 6 тематических карточек в черновиках, с нормами, перечнем документов и ссылками на действующие статические страницы.
- `Судебная практика ДГИ` — ID `6aca8b43f741d6755539f345` — основная коллекция.

Страницы нормативных актов, жизненных ситуаций, госуслуг и судебной практики на публичном сайте пока представляют отредактированный **статический информационный слой**, не динамическую CMS-выдачу новых коллекций. Для запуска динамики нужны дизайн CMS-шаблонов, фильтрация и редакционные правила публикации.

## Техническое масштабирование

На нынешней странице Webflow CMS Collection List отдаёт ограниченный набор опубликованных элементов (обычно до 100). Кнопка «Показать ещё» показывает по три **уже загруженные** карточки. Она не запрашивает следующую порцию из базы. Для цели 1000+ **проверенных** судебных актов нужно внедрить API поиска и серверную пагинацию с безопасным кэшем и ограничением доступа, отделив импорт от публичного поиска.

GitHub Actions: ручной запуск с `upload=false` — без записи в CMS. По расписанию текущий workflow вносит до 50 **кандидатов в черновики**, не проверенных решений и не обязательно 50 новых записей. Парсеры кассации, арбитража и Верховного Суда пока не реализованы. Скрейпинг/автоматизация доступа к судебным ресурсам должны соответствовать условиям их использования.
