# Судебные акты ДГИ: собственный архив полного текста и поисковая оптимизация

**Реализация:** 15.10.2026. **Статус:** код подготовлен в `feature/dgi-offline-completion`, без применения миграций к рабочей БД, без публикации и без merge в `main`.

## Цель

Каждое проверенное официальное решение, определение или постановление суда хранится **в нашем PostgreSQL**, а не только в виде внешней ссылки. Каждому отдельному акту соответствует собственная HTML-страница вида `/sudebnye-akty/<slug>` с точными реквизитами, полным опубликованным текстом, человеческим описанием, прямым официальным источником и связями с другими опубликованными актами по делу.

Это позволяет находить материалы по юридическим формулировкам в тексте как через внутренний русский полнотекстовый поиск PostgreSQL, так и через поисковые системы после разрешённого запуска.

**Важное отличие:** одна исходная судебная *карточка дела* может содержать несколько судебных **актов**: первое решение, апелляционное определение, кассацию, новое рассмотрение. Храним их как отдельные документы, связывая `case_id` и `instance_id`; не склеиваем в неподтверждённый «единый итог».

## Реализованные компоненты

| Компонент | Где хранится и что делает |
|---|---|
| Полный текст | `court_act_documents.full_text` в PostgreSQL; до 2 млн символов на акт, контрольная сумма SHA-256 |
| Судебные реквизиты | Суд, номер, УИД, дата, инстанция, вид акта, предмет; внешний официальный URL |
| Правила публикации | `0005_court_fulltext_publication.sql` — по умолчанию `draft`; отдельные подтверждения источника, текста и проверки персональных данных; изменение текста автоматически отзывает допуск |
| Первичная загрузка | `scripts/import-official-court-act.mjs` — загружает **только полный** локальный `.txt` с безопасными данными в изолированную БД; не публикует автоматически |
| Судебный акт | `apps/web/src/app/sudebnye-akty/[slug]/page.tsx` — полный серверный HTML, собственный `title`, `description`, `canonical`, `CreativeWork` и `BreadcrumbList`, официальный источник |
| Каталог и поиск | `/sudebnye-akty` — поиск по `to_tsvector('russian',full_text)`, номерам дел, суду и темам; разбивка на страницы |
| Ссылки между решениями | При наличии нескольких опубликованных актов одного дела показываются внутренние ссылки |
| Sitemap | В `sitemap.xml` входят **только реально опубликованные** документы; нет дублей / карточек без текста |
| Отсечка черновиков | `SITE_CUTOVER` + `SITE_RELEASE_APPROVED` + действительный `SITE_URL` + `COURT_FULLTEXT_PUBLIC_READS=true` и отдельный статус конкретного акта |

## Как импортировать реальное определение суда в собственную базу

1. Найти **полный текст** именно судебного акта на индивидуальной официальной странице `mos-gorsud.ru`, `*.sudrf.ru`, `vsrf.ru` или `kad.arbitr.ru`. Страница поисковой выдачи или карточка движения без текста не подходят.
2. Скопировать весь уже опубликованный судом текст в локальный UTF-8 файл (привести только переводы строк к `\n`, не переделывать мотивировку и не сокращать). Не помещать файл с персональными данными в публичный GitHub.
3. Проверить ограничения статьи 15 Федерального закона № 262-ФЗ, опубликованное судом обезличивание, отсутствие закрытых категорий и чувствительных сведений. Если источник не подходит, не импортировать.
4. Создать приватный JSON-манифест рядом с текстом, например:

```json
{
  "slug": "2kas-88-21277-2026-2026-07-28",
  "stableKey": "official:ACTUAL_SOURCE_RECORD_ID",
  "caseNumber": "88-21277/2026",
  "courtName": "Второй кассационный суд общей юрисдикции",
  "uid": "77RS0013-02-2025-011552-74",
  "instanceType": "cassation",
  "decisionDate": "2026-07-28",
  "actType": "ruling",
  "topic": "Изъятие жилого помещения для государственных нужд и переселение",
  "officialUrl": "https://2kas.sudrf.ru/modules.php?case_id=18910390&case_uid=207aa87d-e20e-49ea-bd58-14f1bc1f49b7&delo_id=2800001&name=sud_delo&name_op=case&new=2800001&srv_num=1",
  "fullTextFile": "/secure/court-acts/88-21277-2026.txt",
  "seoTitle": "Изъятие квартиры и переселение — кассационное определение № 88-21277/2026",
  "seoDescription": "Судебное определение по делу об изъятии жилья для государственных нужд: полный текст кассации, применённые положения ЖК РФ и источник суда.",
  "editorNote": "Суд рассматривал кассационную жалобу по спору о выселении с предоставлением другого жилого помещения. Ниже приведён официальный текст, а не краткий пересказ.",
  "courtPublicTextConfirmed": true,
  "sensitiveDataReviewedForDraft": true
}
```

**Важно:** `stableKey` в примере — заглушка; перед импортом нужно указать **точный** идентификатор из `court_cases.stable_key` и сверить `court_instances`. Пример **не означает**, что текст № 88-21277/2026 уже загружен.

5. Выполнить только dry-run:

```bash
node scripts/import-official-court-act.mjs /secure/court-act.json
```

6. В изолированном staging окружении с миграцией 0005 и подтверждённым `COURT_IMPORT_ALLOW_WRITE=staging` выполнить явный `--apply` (нужен также `DATABASE_URL`). Это сохраняет текст со статусом `review`, без опубликования.
7. Сверить контрольную сумму, реквизиты, текст и обезличивание. После отдельной технической/редакторской приёмки заполнить `source_checked_at`, `text_verified_at`, `privacy_checked_at`, `reviewed_by`, `published_at` и `status='published'` через защищённый редакционный процесс. **Импорт сам этого не делает.**
8. Только после отдельного разрешения на запуск включить рабочие флаги и проверить реальные HTTP-страницы, sitemap, robots, Search Console и индексирование.

## SEO: критерии каждой страницы

- Один **проверенный акт** — один стабильный человекочитаемый URL. Не делать несколько почти одинаковых страниц под синонимы и ключевые слова.
- В HTML, который отдаёт сервер, находится весь текст, а не iframe со стороннего суда, не только PDF и не JavaScript-загрузка после открытия страницы.
- Уникальные и фактически корректные `title`, `description`, H1; дата, суд, УИД, номер, инстанция, юридическая категория.
- Человекочитаемый обзор **отдельно от текста судебного акта**: предмет спора, пределы рассмотрения, подтверждённый результат и соответствующая проблематика. Нельзя придумывать судебную мотивировку или позицию других инстанций.
- Прямой официальный первоисточник; ссылка на другие опубликованные решения по делу, если они существуют в базе.
- Только одобренные страницы с собственным `canonical` добавляются в sitemap и становятся `index,follow`. Офлайн, черновики и архивные неподтверждённые карточки остаются `noindex`/404.
- Веб-поиск по тексту — отдельная польза читателю, но Google/Yandex **самостоятельно решают**, какие страницы индексировать и ранжировать. Массовое дублирование официального текста без полезных оригинальных пояснений и ссылок может не давать поискового результата.

Официальные рекомендации Google: [канонические URL](https://developers.google.com/search/docs/crawling-indexing/canonicalization), [описание Article / структурированные данные](https://developers.google.com/search/docs/appearance/structured-data/article), [политика против перепечаток без дополнительной ценности](https://developers.google.com/search/docs/essentials/spam-policies). Для судебных актов используется нейтральный `CreativeWork`, без поддельных рейтингов и рецензий.

## Правовые условия

- **Подпункт 1 пункта 6 статьи 1259 ГК РФ:** официальные судебные решения не являются объектами авторских прав. Это не распространяется автоматически на добавленные коммерческие комментарии, фотографии и сторонние базы.
- **Статья 15 закона № 262-ФЗ:** особенности доступности текстов судов общей юрисдикции, исключения для отдельных категорий дел, персональные данные и ограничения на раскрытие. Даже официальный сайт суда требует контроля того, какую часть текста безопасно воспроизводить.
- Сохранять исходное судебное обезличивание и никогда не «восстанавливать» скрытые персональные сведения.
- Индексация не является автоматическим разрешением на распространение персональных данных. Редакционный допуск к отдельному документу проверяется по содержимому.

## Чего пока нет

**Реальные полные тексты всё ещё не загружены:** Neon `dgi-court-importer` создан 16.10.2026, миграция 0005 применена к `main` и `staging`, но полные тексты восьми судебных актов пока не импортированы. Пользователь отдельно запретил публичный deploy. Сейчас создана модель и код, который хранит полные тексты в нашей БД после отдельного импорта. Подготовленные 8 кассационных карточек содержат официальные ссылки и исследованные результаты, но не заменяют требуемый полный текст для публикации.

**Следующие шаги:** собрать 8 опубликованных судебных актов в локальные UTF-8 файлы с проверенным обезличиванием, оформить манифесты, загрузить в staging PostgreSQL, затем остальные по мере появления точного официального акта. Без импорта полного текста **не** открывать их для индексации.


## Очередь первоначальной загрузки 16 дел

Подготовлен машинный реестр `migration/court-fulltext-ingestion-queue-2026-10-15.json`:

- **16** точных официальных ссылок и `stableKey` из существующей базы `court_cases` (вида `official:seed-2kas-...`).
- **8** дел, по которым ранее на официальном сайте суда найден текст кассационного определения или его резолютивная часть, — приоритетный пакет переноса.
- **8** дополнительных карточек, где имеются только реквизиты дела; до появления полного акта создавать SEO-страницу запрещено.
- **0** полных реальных текстов пока фактически загружено в постоянную БД этого проекта; фиктивное содержимое используется только в одноразовом CI.

Это устраняет повторный поиск IDs и позволяет подготовить отдельные приватные манифесты для 8 документов без ошибочного связывания дел и апелляций. Точная загрузка текстов зависит от выделения отдельной PostgreSQL-БД ДГИ и проверки опубликованного судом обезличивания.

**Подтверждение технической работоспособности:** GitHub Actions CI выполняет отдельную серверную сборку с фиктивным доменом и синтетической записью в одноразовой PostgreSQL: проверяет полный текст в HTML, русский поиск, индивидуальный canonical, sitemap и отзыв публикации при изменении текста. Все данные теста удаляются после проверки; никакие фиктивные решения не отправляются в рабочий каталог.
