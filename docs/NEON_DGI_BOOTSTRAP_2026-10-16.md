## Текущие границы выполненного

**Таблицы основной базы** существуют и наполнены первичной метаинформацией. `dgi_cms` выделена, но **служебные таблицы самой Payload CMS не созданы**: они должны создаваться через согласованную миграцию Payload на отдельном защищённом окружении с `CMS_DATABASE_URL`. Нельзя считать CMS подключённой и работающей только по факту создания базы данных.

Neon не подключён к Vercel и нет опубликованного рабочего выпуска. Для этого необходимы секретные `DATABASE_URL`, `CMS_DATABASE_URL` в защищённом хранилище окружения и сквозная проверка приложений. Секреты не сохранять в GitHub. Запуск Vercel только по отдельному разрешению пользователя.

**Полный судебный архив** реализован в коде и проверен на изолированной тестовой базе GitHub Actions; реальные полные тексты опубликованных судебных актов ещё необходимо загрузить с официальных сайтов и проверить пригодность для размещения. Не путать 16 ссылок на карточки судов с 16 полными текстами.

## Проверенные ограничения выпуска

- Без `SITE_CUTOVER=true`, `SITE_RELEASE_APPROVED=yes` и корректного `SITE_URL` контент скрыт.
- Без `COURT_FULLTEXT_PUBLIC_READS=true` чтение полнотекстового судебного архива запрещено.
- `court_act_documents` требует проверки конкретного текста и персональных данных, уникального SEO-текста, редакционного допуска. Изменение содержимого снимает опубликованный статус.
- Исторические записи `webflow_cms_staging` принудительно `verified=false` и `publication_allowed=false`.
- В целях независимой проверки состояния база `main` не переименована в production-сайт: это только основная ветка Neon с черновиками.

## Следующие технические действия

1. В отдельном защищённом окружении развёртывания применить миграции Payload CMS к `dgi_cms`, проверить роли и импорт из сохранённой выгрузки.
2. Подготовить полный текст восьми официально найденных кассационных актов; сохранить только исходный опубликованный и проверенный на ограничения текст в `dgi.court_act_documents` через контролируемый импорт.
3. Проверить всё на `staging`: SQL, полнотекстовый поиск, канонические URL, sitemap, `robots`, перенос вложений, безопасность, backup/restore, независимую юридическую приемку.
4. После отдельного разрешения соединить Vercel с Neon и выполнить согласованный выпуск. При сохранённом запрете публикации `main` GitHub и публичный домен не менять.
