# ДГИ — переход на GitHub → GitHub Actions → Vercel ↔ Neon

Актуальная дата: 18 октября 2026 года.

## Решение об инфраструктуре

- Работа над интерфейсом и публикацией в прежнем конструкторе прекращена. Исторические данные и снимки сохранены в репозитории только как архив миграции, для сверки источников и правовых фактов.
- Единственный будущий источник исполняемого интерфейса — `apps/web` (Next.js); `apps/cms` — редакционный контур Payload CMS.
- Единственный конвейер развёртывания — GitHub Actions и связанный Vercel-проект `dgi-housing-preview`; постоянная база — отдельный Neon-проект `dgi-court-importer`.
- Никаких новых API-записей, черновиков, CMS-публикаций и изменений дизайна в прежней системе.
- `admin@dgi-pravo.ru` добавлен в Next.js в подвал и контакты как редакционный адрес. Существование действующего почтового ящика, MX/SPF/DKIM/DMARC и настройка Timeweb требуют отдельной проверки у владельца домена; отображение адреса на сайте не означает наличие почтового ящика.

## Не выдавать за готовый production

1. Подтвердить полную сверку исходного содержимого, URL, навигации, форм и вложений 33 страниц; отдельно проверить источники 50 CMS-материалов.
2. Закрыть юридическую и редакционную проверку нормативных актов и судебных дел. Ни одна карточка не публикуется на основании одного URL или метаданных.
3. Развернуть приватную CMS с ролями, секретами и администратором; проверить runtime, права доступа и сохранение изменений.
4. Настроить разграниченные доступы к Neon (production и staging), выполнить воспроизводимые миграции, независимую резервную копию и тест восстановления.
5. Завершить браузерную/мобильную/доступностную/SEO-приёмку в **Next.js**, а не в архивном источнике. Установить проверенный HTTPS SITE_URL; подготовить DNS и SSL, не ломая существующую почту.
6. Проверить GitHub Actions, Vercel Deployment Checks, preview и staging DB; только затем PR → main, production deployment, мониторинг, rollback.
7. Только после правового и редакционного допуска активировать `SITE_CUTOVER=true` и `SITE_RELEASE_APPROVED=yes` для production; публикация конкретной записи дополнительно требует персонального подтверждения в БД. До этого тестовые страницы должны оставаться `noindex`.
