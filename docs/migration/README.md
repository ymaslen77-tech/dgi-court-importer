# Перенос Webflow → Next.js — итерация 001

## Что сохраняем
- Рабочий Webflow: https://dgimos.webflow.io/ (остается основным сайтом, ничего не переключаем).
- GitHub `main`: Python-импортёры, scheduled Actions, судебные индексы без изменений.
- Новое приложение: `apps/web` (Next.js + TypeScript, адаптивная чёрно-белая палитра с красным акцентом).
- Webflow slugs и SEO-метаданные из исходного сайта. Оригинальные Webflow pageId сохранены в `src/data/webflow-pages.json`.
- Снимок контента `src/data/webflow-content.json` хранит отобранные *тексты*, а не экспорт CSS/скриптов. Редакционная проверка и перенос изображений ещё требуются.

## Локальный запуск
1. Node.js 24+, npm; клонировать текущую feature-ветку.
2. В корне репозитория: `npm install`.
3. `npm run web:dev` — адрес http://localhost:3000.
4. `npm run web:check`, `npm run web:test`, `npm run web:build`.

Изолированность: базовые зависимости Python по-прежнему устанавливаются отдельно через `pip install -r requirements.txt`. Для локальной базы PostgreSQL и Payload CMS будет отдельная итерация.

## Запрет преждевременной индексации
`PUBLIC_INDEXING_ENABLED` **не устанавливать** до переключения домена и SEO-проверки. По умолчанию все страницы получают `noindex`, а robots.txt запрещает индексирование. При окончательном переключении указать `NEXT_PUBLIC_SITE_URL=https://<основной домен>`, после проверки robots/sitemap/canonical открыть индексацию.

## Важные ограничения первого этапа
- Каталог `/sudebnaya-praktika-dgi` читает только `data/court-catalog.jsonl` (16 официальных карточек-кандидатов), **не выдаёт их за проверенные судебные акты**. Развёртывание отдельно от monorepo root требует указать `COURT_CATALOG_PATH` и доставить этот файл.
- Старые опубликованные Webflow судебные записи должны пройти отдельную миграцию, не смешивать их с кандидатами.
- Payload CMS + PostgreSQL: спроектированы как следующий этап, но не выдаются за уже включённые. Новая версия пока **read-only**.
- Содержание страниц переносится без переписывания правовых выводов. Экспортируемые Webflow элементы могут содержать повторяющиеся блоки, меню и устаревшие ссылки — их нужно вручную нормализовать.
- Не переносить API-токены, приватные настройки, Webflow JS embeds или клиентские данные.
- Дубликаты существующих SEO-страниц нельзя публиковать одновременно на Webflow и тестовом домене.

## Приёмка для переключения домена (последующие PR)
1. Полный независимый бэкап всех опубликованных Webflow страниц, CMS, изображений, ссылок, SEO и медиа.
2. Подтверждение точного состава URL/redirect map; сохранение уже проиндексированных адресов.
3. Устойчивое CMS CRUD с ролями, черновиками, ревизиями, audit logs, миграцией в PostgreSQL.
4. Реальная миграция медиа/изображений и проверка прав на их использование.
5. Нагрузочная и функциональная проверка судебного поиска, пагинации и фильтров.
6. Сборка CI зелёная, мобильный UI проверен; 404, sitemap, canonical, robots, schema.org проверены на staging.
7. Только затем DNS/домен/301 и Search Console / Яндекс Вебмастер.
