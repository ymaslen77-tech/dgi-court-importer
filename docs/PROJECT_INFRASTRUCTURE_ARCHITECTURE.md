# Полная схема разработки, размещения и работы сайта ДГИ

**Канонический документ:** [Стандарт разработки, размещения и эксплуатации сайта](DEVELOPMENT_AND_INFRASTRUCTURE.md), редакция 15.10.2026.

В проекте предусмотрен **один** основной стандарт, чтобы правила развития инфраструктуры, разграничение сред, выпуск, миграции, резервное копирование и rollback не расходились между двумя документами.

Документ `DEVELOPMENT_AND_INFRASTRUCTURE.md` содержит:

- Семь основных звеньев: локальная разработка, GitHub, GitHub Actions, Vercel, Neon, домен/DNS и пользователи.
- Дополнительные компоненты: worker/очереди, планировщик, S3, авторизация, мониторинг, резервное копирование и защита.
- Раздельные Development, CI, Preview, Staging и Production.
- Десять этапов от ветки и Pull Request до публикации, контроля миграций, наблюдаемости и rollback.
- Разграничение **целевой архитектуры** и **реально реализованных интеграций**.

Целевая схема: `Разработка → GitHub → GitHub Actions → Vercel ↔ Neon`. Пользовательский путь: `Пользователь → Домен/DNS → Vercel → Серверная логика → Neon`.

**На текущем этапе** — только GitHub и автоматические проверки. Никакого Vercel deployment, переключения DNS, изменения работающего сайта или объединения с `main`. Neon `dgi-court-importer` реально создан 16.10.2026, schema + архивная метаинформация импортированы в `main`/`staging`. Runtime Vercel и Payload пока не подключены: [подробности](NEON_DGI_BOOTSTRAP_2026-10-16.md). Содержание без подтверждённых юридических первоисточников не публиковать.

См. также [условия готовности к выпуску](RELEASE_READINESS.md) и [отчёт по офлайн-проверкам](OFFLINE_COMPLETION_QA_2026-10-14.md).
