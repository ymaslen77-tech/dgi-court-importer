## Первый администратор — только персональное безопасное создание

1. Убедиться, что выбранный почтовый адрес реально принимает письма. Не использовать случайный/неработающий email.
2. На доверенном локальном компьютере владельца открыть проект, установить зависимости (`pnpm install --frozen-lockfile`) и получить **только staging CMS** `CMS_DATABASE_URL` и `PAYLOAD_SECRET` из Vercel через защищённый доступ.
3. В доверенном процессе задать временные переменные окружения `CMS_BOOTSTRAP_CONFIRM=yes`, `CMS_BOOTSTRAP_EMAIL=<адрес владельца>`, `CMS_BOOTSTRAP_PASSWORD=<сильный личный пароль длиной >=16>`. Пароль не писать в чат, GitHub, PR или workflow inputs.
4. Выполнить `pnpm --filter @dgi/cms bootstrap:admin` ровно один раз. Скрипт откажет, если в базе уже есть учётные записи.
5. Сразу удалить переменные загрузки из окружения, проверить вход в `/admin` и роли. Не включать регистрацию для анонимов и не выключать Vercel Authentication.
6. Не выдавать `production` или доступ к публичной БД автоматически. Сначала принять рабочий процесс, публиковать только после правовой редакционной проверки.

## Известные ограничения
- Локальная загрузка медиа **не долговечна** в бессерверной среде. До подключения отдельного S3-совместимого хранилища **не загружать рабочие файлы**.
- Изменения статуса редакционных материалов не означают автоматическую публикацию: мост между Payload и таблицами публичного сайта ещё требует приёмки и тестов.
- Зафиксировать независимый backup/restore, аудит прав, ролевую матрицу и мониторинг прежде чем переносить CMS на реальный production.
