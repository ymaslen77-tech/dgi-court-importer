# Перенос сайта Webflow → Next.js (этап 1)

**Состояние:** безопасная ветка разработки. Публичный сайт по адресу [dgimos.webflow.io](https://dgimos.webflow.io/) **не изменён**. Ничего не переключалось на новый сервер.

## Что уже перенесено

- **33 обычные опубликованные страницы Webflow**: URL-slug, заголовки, SEO title/description, извлечённые тексты H1-H6, абзацы, списки и ссылки. Снимки в `migration/pages-part-1..4.json` (не ручной рерайт).
- **4 коллекции Webflow CMS:** 37 судебных карточек (22 публичные и 15 черновиков), 4 нормативных материала, 6 ситуаций, 3 новости. Полный снимок источника: `migration/webflow-cms.json`. Никаких черновиков в публичную выдачу новой версии не переносить.
- **Next.js + TypeScript + Tailwind** в `apps/web/`: главная, общий адаптивный интерфейс, 32 тематических маршрута, SEO metadata, sitemap/robots, 22 публичные архивные карточки по адресам `/dgi-court-cases/:slug`.
- **Первая PostgreSQL-схема для staging:** `database/001_webflow_staging.sql` и повторяемый импорт `scripts/seed-webflow-staging.mjs`.
- Импортёры суда/новостей на Python и их Actions **не изменены**.

Это **первый рабочий слой миграции**, а не финальная точная копия Webflow. Исходные фотографии, CSS/анимации Webflow и Webflow CMS Template ещё не перенесены как редактируемые компоненты. Новая версия пока читает JSON snapshots без SQL-запросов; PostgreSQL на этом этапе служит staging.

## Запуск

Требуется Node.js 22+ и npm.

```bash
npm install
npm run test:content
npm run typecheck
npm run dev
```

Открыть `http://localhost:3000/`. Для сборки: `npm run build`, затем `npm run start`.

По умолчанию новое приложение закрыто от индексации: robots.txt disallow и metadata `noindex`. Sitemap пуст до явного `ENABLE_INDEXING=true`. Canonical пока указывает на действующий Webflow. **Не включайте indexing и не переключайте DNS**, пока не завершён перенос и не сверены страницы.

## PostgreSQL staging (необязательно для просмотра)

```bash
# Создайте локальный пароль Postgres и передайте его через переменную окружения.
export POSTGRES_PASSWORD='replace-this-in-dev'
docker compose up -d postgres
export DATABASE_URL='postgresql://housing:replace-this-in-dev@localhost:5432/housing'
npm run stage:dry-run
npm run stage:apply
```

Импорт безопасно повторяется. Судебные записи из Webflow сохраняются вместе с флагами публикации/верификации и **не объявляются проверенными**. Публикация после импорта не выполняется.

## Важные SEO-инварианты

- Все 33 исходных pathname сохраняются посимвольно (включая кириллицу внутри контента; URL латиницей).
- На каждой странице один H1; все остальные извлечённые H1 понижаются до H2.
- Источники выводятся текстом, без внедрения произвольного HTML.
- Индексация только после утверждения домена, проверки canonical, robots.txt, sitemap.xml, 301-редиректов и реальных документов.
- Судебные карточки с непроверенными актами получают `noindex` вне зависимости от общей настройки.
- Черновики Webflow не публикуются автоматически.

## Следующие задачи / критерии готовности

1. **Дизайн:** перенести собственные лицензированные изображения, типографику, компоненты и проверить мобильные версии; не использовать ссылки на сторонние фото без права публикации.
2. **CMS:** подключить Payload CMS с PostgreSQL; настроить редакционные роли, черновики, историю изменений и миграцию rich-text без потери вложений.
3. **Судебная практика:** создать нормализованные таблицы дел, инстанций, источников и статусов; подключить существующие Python workers к отдельному ingestion API/очереди и добавить фильтруемый поиск. В базе 16 кандидатов из GitHub, не смешивать их с 37 карточками Webflow.
4. **Тестирование:** проверить сборку в GitHub Actions, ссылки, robots/canonical, визуальный результат, публикацию статей; подключить E2E smoke-тесты.
5. **Переключение:** полный список URL, 301 для изменившихся, резервная копия, параллельный прогон, затем по отдельному согласованию DNS.

Ни один шаг сам по себе **не означает**, что перенос завершён или что текущий Webflow можно удалить.
