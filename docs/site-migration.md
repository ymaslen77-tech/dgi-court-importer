# Этап 1: безопасный перенос Webflow → код (13 октября 2026)

## Источник, ветка, ограничения

- Действующий сайт: https://dgimos.webflow.io/; Webflow site ID: `6aca6bde03aad0f2e3c19259`.
- Исходный репозиторий содержит рабочие Python-модули `importer.py`, `news_importer.py`, `court_catalog.py`, папки tests/data, GitHub Actions. Файлы **не трогаем**.
- Новое приложение: каталог `site/` в той же репозитории. Разработка только в отдельной ветке, без автоматического мержа.
- В Webflow найдено **38 страниц**, в том числе один внутренний устаревший макет и страницы коллекций; 33 обычных страницы включены в снимок миграции после исключения архивной. Главная имеет slug `''`.
- Снимок: `site/src/data/webflow-pages.json`; номера страниц `id`, title, SEO title/description, slug. Это **не содержимое** редакционных материалов.
- В каталоге-кандидате `data/court-catalog.jsonl` зафиксировано 16 карточек; дубли публикаций в Webflow нельзя складывать с этим количеством как уникальные дела. Новый frontend показывает только метаданные и предупреждение о неверифицированности.

## Приёмка и безопасные ограничения

1. Все действующие пути Webflow сохраняются в Next.js; не подменять путевые адреса переводом с русского или автоматической латинизацией. Для двух похожих страниц о выморочном имуществе пока не выбирать canonical автоматически: нужно редакционное решение и 301.
2. Сайт остаётся noindex, пока не совпадают основной контент, все SEO title/description, canonical, ссылки, изображения, юридические документы и корректность карты редиректов.
3. У новости необходимы оригинальный источник, корректный статус нормы и редакционная проверка. У судебного акта — ссылка на официальный текст, дата проверки; только найденная карточка дела не равна судебному акту.
4. Редакционные страницы создаются в Payload как `metadata_only` **draft**, никогда не публикуются автоматическим импортёром.
5. Секреты хранятся только в env/CI Secrets. Никаких ключей Webflow в JS клиентского приложения.
6. Старая инфраструктура Webflow и рабочие Python Actions продолжают работать без переключения DNS.

## Этапы после первого PR

**Этап 2. Полный экспорт.** Выгрузить страницы и CMS в проверяемый JSON/HTML, сохранить хэши и дату, собрать ссылки и реальные изображения с лицензиями. Перенести HTML в безопасную форматную модель (sanitization, без исполнения пользовательских скриптов). Сверить тексты редактором.

**Этап 3. Судебная база.** Реальные таблицы PostgreSQL + ingest worker, верификация первоисточников, дедупликация по УИД и инстанциям, полнотекстовый поиск и фильтры. `site/sql/001_court_ingestion.sql` — первоначальный SQL-каркас, **не исполненная миграция**.

**Этап 4. Редакция.** Импорт новостей и юридических ситуаций, права пользователей, журнал корректировок, проверка ссылок, запрет автоматической публикации незавершённых правовых материалов.

**Этап 5. SEO и запуск.** Визуальное сравнение desktop/mobile, PageSpeed, sitemap, канонические URL, 404/301, robots, schema.org; проверка индексации Яндексом. Только затем переключать домен.

## Запуск этого этапа

```bash
cd site
cp .env.example .env
# set POSTGRES_PASSWORD, DATABASE_URL, PAYLOAD_SECRET to non-default values
# docker compose up -d postgres
pnpm install --no-frozen-lockfile
pnpm dev
pnpm test
pnpm typecheck
pnpm import:pages
```

**Статус:** файлы структуры созданы в ветке. Node/Payload сборка, миграция данных, локальный smoke test, PostgreSQL и deploy требуют отдельной фактической проверки. Не отмечать как passed до прохождения CI.
