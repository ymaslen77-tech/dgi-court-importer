# Единая справочная служба Москвы — миграция в Next.js

В этом же репозитории начат перенос [Webflow-сайта](https://dgimos.webflow.io/) в `apps/web` (Next.js, TypeScript, Tailwind). Сохранены существующие Python-импортёры судебной практики и новости.

**Статус:** первая версия приложения и снимки 33 страниц + 22 опубликованных судебных метаданных в ветке `feature/nextjs-webflow-migration`. Это не готовое переключение домена: CMS/DB runtime, изображения и SEO QA остаются в работе. На тестовой версии индексация отключена до флага `SITE_CUTOVER=true`.

- [Инструкция по миграции и незакрытые задачи](docs/NEXTJS_MIGRATION.md)
- Команды: `corepack enable && pnpm install --no-frozen-lockfile && pnpm test && pnpm build && pnpm dev`
- Не публикуйте сырые Webflow CMS-данные и секреты; `scripts/export-webflow.mjs` складывает backup в gitignored `.migration/`.
- Действующий Webflow не отключён, текущая ветка `main` не заменяется до ревью.

# DGI Court Importer

Консервативный загрузчик опубликованных судебных актов с участием Департамента городского имущества города Москвы в Webflow CMS.

**Статус:** код импортёра подготовлен. Импорт не включён, пока не заданы `WEBFLOW_TOKEN` и прямой URL JSON-выгрузки `COURT_DATASET_URL`, не проверены условия использования и фактическая схема данных.

## Назначение

- Цель: не менее 1000 **проверенных** судебных актов в базе; пополнение — **до 50 подходящих документов в неделю**.
- Источник кандидатов: официальные открытые данные [судов Москвы](https://data.mos-gorsud.ru/opendata), при условии доступа к законно распространяемой машиночитаемой выгрузке.
- Импортируются **черновики**, а не опубликованные материалы: запись в статистическом наборе ≠ проверенная резолютивная часть судебного акта.
- Никакого обхода CAPTCHA, блокировок, лимитов или сбора персональных данных сверх необходимого.
- Проверка дублей по хешу характеристик акта и URL, в том числе в существующей CMS.
- Не выдаём цель 50/неделю за гарантированный результат: источники и качество данных могут ограничивать выдачу.

## Webflow

Сайт: `6aca6bde03aad0f2e3c19259`. CMS Collection: `6aca8b43f741d6755539f345`.

На дату первоначального развёртывания коллекция имела 29 записей (22 опубликованные, 7 черновиков). Импортёр не изменяет и не удаляет эти записи.

**Внимание: `https://data.mos-gorsud.ru/api/opendata/json` нельзя использовать как `COURT_DATASET_URL`: вероятно, это экспорт реестра наборов данных, а не сами судебные дела. Нужен отдельный JSON-файл конкретного набора «Информация по гражданским делам первой инстанции». Импортёр отклоняет известный адрес экспорта реестра.**

## Найденный официальный набор данных

«Информация по гражданским делам первой инстанции, находящимся в судах общей юрисдикции города Москвы»:

```text
https://data.mos-gorsud.ru/api/opendata/1577116594824-casesgroupfirstcivilhxvgb/latest/data/json/
```

Это предполагаемый прямой адрес JSON-файла для GitHub Variable `COURT_DATASET_URL`; портал подтверждает сам набор и размер порядка 622 МБ, однако полный ответ этого API из среды разработки не был получен. Следовательно, схема сырого JSON **пока не подтверждена**. При первом запуске используйте локальную проверку схемы / dry-run, проверьте данные реального образца и отсутствие ошибок. Не переходите к публикации непроверенных данных.

Источник предоставляет перечень дел и связи с судебными актами, но наличие карточки или ссылки не гарантирует правильное определение результата рассмотрения. Код добавляет только черновики для последующей редакторской проверки.

## Первый безопасный запуск через GitHub Actions

После создания секрета `WEBFLOW_TOKEN` и переменной `COURT_DATASET_URL`:

1. Откройте **Actions → DGI court data — staged import → Run workflow**.
2. Укажите `batch_size=5`, а `upload=false` (флажок **выключен**).
3. Запустите. Workflow скачивает полный JSON (~622 МБ), прогоняет тесты, анализирует дела, но **не записывает их в Webflow**.
4. Проверьте логи: `scanned`, `matches`, `candidates`, `dry_run: true`.
5. Только после проверки можно использовать `upload=true`: новые записи создаются **строго как Draft**, не публикуются.

Подтверждённые историческими данными ключи: `courtName`, `number`, `uid`, `participants[]/displayName`, `attachments[]/link`, `url`, `publishingState`. В выгрузке также могут встречаться строки, **у которых нет файла судебного акта** — они остаются черновыми кандидатами со ссылкой на официальную карточку дела; результат по полю `publishingState` автоматически **не признаём проверенным судебным решением**.

Еженедельный workflow рассчитан на загрузку максимум 50 кандидатов в черновики. Цель 1000 подтверждённых решений потребует проверки актов и отдельно реализованного полноценного поиска.

## Установка и проверки

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Локальная проверка без записи в CMS:

```bash
python importer.py --input official-courts.json --source-label https://data.mos-gorsud.ru/opendata --limit 50
```

Загрузка **черновиков** (без публикации):

```bash
WEBFLOW_TOKEN=... python importer.py --input official-courts.json --download-url https://data.mos-gorsud.ru/.../actual.json --limit 50 --upload
```

Вместо передачи токена в командной строке используйте переменную окружения или секрет GitHub Actions. Не сохраняйте токен в файлах проекта.

## GitHub Actions

В настройках репозитория **Settings → Secrets and variables → Actions**:

- **Secret** `WEBFLOW_TOKEN`: токен Webflow с разрешениями `cms:read`, `cms:write` к соответствующему сайту.
- **Variable** `COURT_DATASET_URL`: **прямой URL JSON-файла**, доступный без обхода защитных мер; HTML-страница каталога не подходит.

Workflow `.github/workflows/weekly-dgi.yml` запускается по понедельникам в 06:00 UTC (09:00 МСК) и вручную. Пока переменные не установлены, проверка конфигурации безопасно завершится ошибкой без загрузки записей.

Для одноразовой начальной партии можно вручную запустить workflow c `batch_size=1000`, однако это только лимит **черновых кандидатов**, не обещание 1000 проверенных решений.

## Ограничения и план до производства

1. Подтвердить URL и формат именно той официальной JSON-выгрузки, которую будем загружать.
2. Протестировать маппинг полей на реальном образце, а не предполагать совпадение названий.
3. Проверять, что ДГИ действительно является участником дела; различать суд, УИД, инстанцию, номер и ссылки.
4. Проверять сам текст решения, резолютивную часть и историю апелляций — **только после этого** переводить запись из черновика.
5. Разработать постраничный/серверный полнотекстовый поиск для 1000+ документов: клиентский фильтр Webflow по первой сотне карточек не решает эту задачу.
6. При необходимости подключить отдельный БД/поисковый сервис. Webflow остаётся публичным CMS и интерфейсом.
